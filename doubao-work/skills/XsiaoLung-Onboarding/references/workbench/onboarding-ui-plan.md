# Onboarding 工作台 · 交互 UI 集成方案（v0.1）

> 2026-09-11 · 目标：把 onboarding 从"文字对话"升级为"可交互 AI 助理界面"
> 用户点名的组件库：Beautiful UI、beUI、AI Elements、Generative Loaders、shadcn/ui、React Bits Pro、AIUI Components

---

## 一、核心判断（先说结论）

**这些库不能"直接安装"进豆包工作**——它们都是 React / Next.js / Tailwind 生态的组件库（copy-paste 源码式），豆包工作技能没有构建链。但有两件事完全可行：

1. **设计语言可 100% 落地**：loading / thinking / streaming 状态、气泡对话、动效反馈、bento 布局、玻璃卡片——全部可以用原生 HTML/CSS/JS 手写实现，放进豆包工作的三种承载形态。
2. **三种承载形态已全部打通**（含刚确认的飞书能力）：
   - **A · 对话内交互**：豆包工作回答里直接渲染可点击的 HTML 组件（renderer），"让用户一个个选"就是这种体验
   - **B · 独立 HTML 工作台**：生成一个自包含的 `.html` 交互应用（onboarding 工作台），浏览器直接打开
   - **C · 飞书文档 / 多维表格**：飞书现已支持上传 `.html` 文件在文档里以预览视图查看和切换代码视图（飞书云文档功能更新日志）；多维表格仪表盘/应用模式支持「内嵌网页」挂载外部页面（多维表格帮助文档）

## 二、组件库 → 设计语言 → 落点映射

| 组件库 | 借鉴什么 | 落在豆包工作的哪里 | 形态 |
|---|---|---|---|
| shadcn/ui | 基础组件规范：按钮/卡片/输入/进度条（Tailwind 风格） | 工作台全部基础控件 | B/C 手写 |
| Beautiful UI | AI 原生状态：thinking 动画、streaming 文字点、任务进行卡 | 提问培训的"豆包在思考"、出题等待 | A/B |
| AI Elements | 消息气泡、推理面板、工具调用展示（基于 shadcn） | 提问培训聊天式界面、问答带出处 | A/B |
| beUI | 按钮动效、菜单交互、状态切换细节 | 破冰选卡、旅程导航、答题按钮反馈 | A/B |
| Generative Loaders | skeleton / shimmer / typing dots 加载动效 | 生成计划、装载文档、出题时的等待反馈 | A/B |
| React Bits | 文字动画、渐变背景、bento 布局（Pro 是组合式页面模块） | 工作台首页氛围、旅程总览仪表盘 | B |
| AIUI Components | 中文适配的 AI 专属组件（聊天/对话场景） | 提问培训的中文话术 + 气泡样式 | A/B |

**落地方式**：不引 npm、不引框架，把以上设计语言浓缩成一份"工作台设计规范"（色板/圆角/字号/动效），手写原生 CSS/JS 组件。参考 beUI 的做法——组件源码可直接给 AI 读（beUI 提供 llms.txt 端点供 coding agent 读取），我们反着来：由豆包工作技能直接产出这些组件。

## 三、三种承载形态（按用户旅程排）

### 形态 A · 对话内交互（立即体验，"让用户一个个选"）

SKILL.md 增加「交互工作台」指引：每个模块渲染一个交互 HTML 块——

| 旅程模块 | 对话内交互组件 |
|---|---|
| 破冰 | 心情/人格选卡（点选即反馈）+ 随机话题按钮 |
| 认识工具与团队 | 答题卡片：点选项→即时判分→动画对勾/叉→得分 |
| 提问培训 | 迷你聊天窗：场景出题→用户输入→BGTA 规则评分→理想回答 |
| 规划 | 三步向导表单→生成 30/60/90 计划卡 |
| 解压 | 方块呼吸动画（4-4-4-4 节拍）+ 54321 五感步骤卡 |

数据来自装载的 onboarding 地图（mock 演示时来自 mock 文档）。每个交互块都要带"继续对话"的落点，不把用户困在 HTML 里。

### 形态 B · 独立 HTML 工作台（全功能单文件）

技能按模板生成 `onboarding-workbench.html`（自包含、零依赖、离线可用）：

- 五站导航 + 旅程进度条（当前站高亮）
- 内置装载后的四张地图数据（提问路径/技术栈软件/组件网址/日程组织）
- 五模块完整可交互（见上表，全部可点可玩）
- 产出可交付：浏览器打开 / 上传飞书云盘 → 在飞书文档中以预览视图查看 / 分享给新人

### 形态 C · Base 智能文档（飞书多维表格）

| Base 能力 | 用在哪 |
|---|---|
| 多维表格（数据表） | 四张地图直接落成 4 张表（渠道清单/软件清单/网址清单/日程），天然可筛选、可协作 |
| 题库 CSV 导入 | 现有 knowledge/*.csv 格式与多维表格导入兼容，答题数据可统计 |
| 仪表盘图表 | 答题正确率、旅程完成度、各渠道响应统计 |
| 仪表盘/应用模式「内嵌网页」 | 把工作台 HTML 托管后 iframe 挂进仪表盘，Base 内直接玩 |
| 飞书文档插入 .html | 上传工作台文件，文档内直接预览渲染效果 |

## 四、"一键安装"的完整链路

```
第 0 步（用户·一次）  导入 XsiaoLung-Onboarding 技能 → 创建伙伴勾选技能
第 1 步（新人）       说「开始 onboarding / 生成我的工作台」
第 2 步（伙伴）       装载 onboarding 文档（链接/粘贴）→ 输出四张地图确认
第 3 步（伙伴）       可选三件套交付：
                      A. 对话内交互模块（立即可玩）
                      B. onboarding-workbench.html（全功能工作台文件）
                      C. 四张地图 Base 表 + 仪表盘（协作与统计）
第 4 步（新人）       走完五站旅程 → 使用中沉淀新 Q&A
第 5 步（进化）       定时任务整理 → 题库/地图更新 → 下批新人受益
```

## 六、风险与边界

- renderer 单块 ≤300 行：复杂交互拆多个块，对话内组件保持精简
- 工作台是"演示/自用"层：真正的成长闭环（沉淀→进化）仍在对话里由 skill 驱动
- mock 与真实数据边界保持（工作台页脚标注）
- 飞书 .html 预览对交互脚本支持有限（静态渲染为主），完整交互体验用浏览器打开工作台文件
