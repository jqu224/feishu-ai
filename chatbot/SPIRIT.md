# SPIRIT · 菜单子吊死鬼模式

本文件是「吊死鬼（Hangman / 猜单词）」玩法的结局反馈规范，**所有架构**都必须遵守，包括（但不限于）飞书 AI chatbot。新增任何载体（新 bot、新前端、新卡片模板）时，先读这份文件。

## 一、输了（机会用完）

- 最后**必须输出一个吊死鬼 ASCII 图案**（完整绞架 + 挂上去的小人），不能只用文字带过。
- 标准图案（各载体保持一致，放进等宽代码块展示）：

```
  +---+
  |   |
  O   |
 /|\  |
 / \  |
      |
=========
```

## 二、赢了（猜出单词）

- (a) 必须报告三项战绩：
  - **答对多少次**（命中的字母次数）
  - **错了几次**（猜错的字母次数）
  - **正确率**（答对 ÷ 总猜测次数，百分比）
- (b) 同时也**必须输出一个庆祝的 ASCII 图案**。标准图案：

```
 * \o/ *
 *  |  *
 * / \ *
```

## 三、基调：及时反馈 · 正能量反馈 · 快乐

- 结局反馈要**立刻给出**，和结果同屏出现，不让用户再点一步。
- 赢了要具体地夸（晒战绩），输了要轻松地鼓励（“下次一定”），绝不阴阳怪气、绝不冷场。
- 无论输赢，都给出「再来一局」的出口，让快乐延续。

# SPIRIT · 卡片设计系统（所有架构通用）

以下规范适用于本仓库全部卡片，也适用于未来任何新载体。改样式前先读这里，`test/design.test.js` 会把这些规则锁成回归测试。

## 四、Layout 规范：手机和电脑都必须好看

1. **单行按钮 ≤ 3 个**；超过 3 个的密集阵列（如键盘）按 ≤ 7 个分行。例外：变形球操作行（变/转/放大/缩小）4 枚极短按钮单行横排（2026-09 用户决策）——操作工具行参照底部导航行处理，必须 `flex_mode: 'none'` 强制单行。
2. **固定行必须 `flex_mode: 'none'`**（强制不换行、列等宽收缩）：键盘行、底部导航行等「错一个位就破相」的行一律用 `'none'`；只有允许流式换行的松散内容才用默认 `'flow'`。
3. **同一行内元素类型必须统一**：按钮行就全是按钮（含已失效的占位），禁止按钮和 markdown/文本混排 —— 两者行高不同，手机端必错位。
4. 选项类入口按数量平铺（2026-09 用户决策，对齐石头剪刀布的点击手感，走 `cards.js` 的 `tileButtons`）：2 个→一行两列；3 个→一行三列；4 个→2×2 田字格；超过 4 个按 ≤ 3 个分行。按钮在列内 `width: 'fill'`，天然可点击。适用范围：剧情选项、人格测试选项。例外：答题选项带 A./B. 字母前缀且文案较长，保持竖排全宽。
5. **入口列表页用两列田字格**：玩法/题库/剧本等入口列表，单元格 = 一个 primary 按钮 + 按钮下方一行 notation/grey 说明，放在同一 column 里，两个 column 组成一行 columnSet（默认 bisect）；奇数个时最后一行只放一个单元格。答题/剧情选项不受此条影响，仍按第 4 条竖排全宽。

## 五、Icon 规范：每卡有图标，同卡不重复

1. **每张卡片 header 必须带 icon**（data icon / standard_icon / custom_icon 均可），图标全部走 `src/icons.js` 注册表，正文禁止 emoji（变形球、提神活动的 emoji 是画面像素，豁免）。
2. **同一卡片内 icon 不重复**：header icon 与正文 icon 不重；同卡多个同语义入口按钮（如题库列表、剧本列表）不挂 icon，用文字区分。
3. icon 颜色跟随本卡 topic 强调色，禁止彩虹图标。

## 六、配色规范：一个 topic 一个色板

每个 topic 一种 header 主题色 + 同色 icon/tag，**全局互不撞色**；同 topic 的衍生卡共享色板。statRow 等统计块保持 grey-50 中性表面（“白光”底），色彩只落在数字与文字上 —— 这个手感很好，保留。

**选项卡级配色层（2026-09 用户决策）**：题库 / 测试套件 / 冷知识这类「从列表点进去的内容卡」，一卡一色，**选项卡之间互不重复**（`test/design.test.js` 有回归测试锁定）。选项卡层与 topic 层允许跨层复用颜色——选项卡只出现在各自列表页的语境里，不会与其他 topic 卡同屏撞色。

## 七、庆祝特效规范：结局必庆祝

1. **任何玩法的结局卡**（答题成绩、测试结果、剧情结局、猜单词胜负……）都必须原地重写当前卡片，展示庆祝特效。
2. **选型决策：用 ASCII，不用 GIF。** 理由：飞书卡片的图片必须先上传素材拿 `img_key`，无法内联自动播放，且卡片原地更新时图片重新加载会闪一下；ASCII 放 markdown 代码块里零资产、零延迟、双端等宽对齐，与本规范第一节的吊死鬼图案风格统一。
3. 标准庆祝图案（`cards.js` 的 `CELEBRATION` 常量，各 topic 按气质选用）：

```
trophy（答题成绩）   fireworks（剧情结局）  sparkle（测试结果）   cheer（猜单词胜利）
  _______               .  . .  .               *  .  *              * \o/ *
 |       |              . \|/ .                  . * .               *  |  *
 | winner |          ————  •  ————                * ˘ *              * / \ *
 |_______|              . /|\ .                  *  .  *
   |   |
  _|   |_
 (_______)
```

4. 输 / 平庸结局不堆庆祝，但也要有一句温暖的即时反馈（正能量原则见第三节）。

## 八、审美调性：克制的单强调色

总纲：**Uber 的骨架 + Apple 的留白 + Google 的语义色 + Snapchat 的一点活泼。**

- **Uber 式骨架**：黑白灰撑起 90% 的界面 —— 中性表面（grey-50）、灰阶辅助文字、清晰层级，信息永远比装饰重要。
- **Apple 式克制**：一卡一个视觉焦点；能省的分隔线就省；字号档位克制（正文 normal、辅助 notation、数字 heading-2），不做花哨堆叠。
- **Google M3 式语义色**：颜色只表达语义（状态、强调、topic 归属），不做多 hue pastel 拼接；色彩落在文字和数字上，不糊大面积色块。
- **Snapchat 式活泼**：每个 topic 只允许**一个**强调色负责个性（见色板表），活泼收在这一点里，不外溢。
- **Instagram 式渐变：明确放弃。** 飞书卡片不支持渐变背景，强行模拟只会脏；用纯色 + 留白达到同等的现代感。
- **画面本体豁免**：提神活动 / 变形球画布内的 emoji 像素渐变属「画面本体」，不是卡片背景渐变，不受上一条「放弃渐变」约束。画布纪律：提神活动是浅色底（⬜）+ 单码点方块像素 + 确定性渐变；变形球是 ⚪ 留白底 + 双色系色板、13×13 画布，图案由种子程序化生成（万花筒象限折叠 / 拼布旗 / 海螺螺线 / 五角星 / 三角毯 / 曼陀罗），整体装进等宽代码块「终端会话」（$ 命令行带 --seed + 像素输出 + > 状态行）的 CLI/TUI 风。
