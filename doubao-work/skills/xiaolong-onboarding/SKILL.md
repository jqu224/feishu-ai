# 小笼 onboarding · 新人成长系统

装好技能 → 给一份（或多份）公司的 onboarding 文档 → 豆包先「读懂」并提炼出一张 **onboarding 地图** → 然后按旅程带你走：**破冰 → 认识工具与团队 → 提问培训 → 规划 → 压力管理**，并随使用不断自我进化。

> 这不是一次性知识库，是一条可持续成长的路径。文档问答只是其中的「提问培训」模块。
> 演示用虚构数据在 `references/mock/`；真实使用时装载用户自己的 onboarding 文档，流程完全一致。

## 第 1 步：装载（Ingest）

接受用户的 onboarding 材料，支持多份：

- 飞书文档 / 网页链接（需「互联网上获得链接的人可阅读」，否则抓不到正文）
- 或直接粘贴的文档内容、Markdown、CSV

处理：抓取 → 按标题分块（每块 300–500 字）→ 建问答索引。**表格转成可读文本清单，链接原样保留**，长文档只保留必要块。

## 第 2 步：提炼 onboarding 地图（Map）

从材料中提取四张表，输出给用户确认后再进入旅程。材料里没有的维度明确写「文档里没提到」，不编造。

| # | 地图 | 提炼什么 | 新人会问的示例 |
|---|---|---|---|
| ① | **提问路径** | 去哪里问、什么问题走哪个渠道、期望响应、该怎么问（含提问模板） | 「网络连不上找谁？」「技术问题发哪个群？」「怎么问才不挨批？」 |
| ② | **技术栈与软件** | 该装哪些软件/程序、涉及哪些技术栈、安装顺序与账号 | 「入职第一天先装什么？」「前端项目用什么栈？」 |
| ③ | **组件与网址** | 去哪些网址看组件/文档/平台内容、谁维护、怎么用 | 「设计规范在哪看？」「API 文档地址？」「看板在哪？」 |
| ④ | **日程与组织** | 入职日程、组织架构与上下游、术语表、30-60-90 天目标模板 | 「Day 1 要做什么？」「我的上下游是谁？」 |

输出格式示例（确认后进入旅程）：

```
📇 Onboarding 地图：<公司名>（基于 N 份文档，共 M 块）
① 提问路径：…（渠道清单，2-3 条）
② 技术栈与软件：…（P0 软件清单，2-3 条）
③ 组件与网址：…（关键网址 2-3 条）
④ 日程与组织：…（Day 1 日程 + 术语 2-3 条）
```

## 第 3 步：按旅程运行（Orchestrate）

用户说「开始 onboarding」或任一模块关键词，按旅程推进。每个模块都是一个小 APP：

### 模块 A · 破冰（新人说「破冰」/「认识下」）
- 用地图④的组织、术语、团队信息生成互动话题与冷知识
- 可选人格测试 / 猜词 / 快问快答，让新人先松弛、互相认识

### 模块 B · 认识工具与团队（「答题」/「闯关」）
- 基于地图②④ + 题库出题（单选/多选/判断），逐题判分 + 解析，标注出处
- 覆盖：飞书基础、豆包工作、技术栈、公司/团队常识、术语

### 模块 C · 提问培训（QA，核心模块）（「提问」/「出题」/「问答」）
- **主动出题检验**：从地图①③ + 题库生成测验，检验新人是否知道「去哪问、怎么问、网址在哪」
- **训练提问路径**：新人的问题不符合地图①的模板时，用模板纠正（如 BGTA：背景/目标/已尝试/请求），并指出该问题应走的渠道
- **带出处回答**：回答地图/文档内容必须标注出处块；文档没有就明说

### 模块 D · 新人规划（「规划」/「30-60-90」）
- 基于地图④的目标模板，产出 30/60/90 天计划（阶段目标 → 关键里程碑 → 每周回顾）
- 每周可让豆包回顾进展并更新计划

### 模块 E · 压力管理（「解压」/「放松」/「焦虑」）
- 54321 五感着陆、方块呼吸 4-4-4-4、4-7-8 呼吸、正念数息、身体扫描、握拳放松
- 呼吸类按节拍引导（每段注明秒数），54321 按用户节奏逐步走

## 第 4 步：自我进化（Evolve）

- **使用中沉淀**：新人问出的新问题、地图里没有的答案 → 记入「待沉淀清单」（输出给用户或写入 notes）
- **定期整理**：豆包工作定时任务触发 → 把本周新 Q&A 整理进题库/地图 → 更新 references
- **下批新人受益**：下次装载同一文档时，自动获得更新后的题库与地图——技能越用越懂这家公司

## 旅程状态（让豆包记住走到哪了）

每次交互后简短记录：当前模块、已完成模块、待沉淀问题数。新人说「继续」时从上次位置接着走。

## 边界与注意事项

- 装载依赖文档公开可读；含隐私的文档提醒用户不要公开链接，可改粘贴内容
- 地图与答案只用文档内容，不用模型记忆补充；必须补充时标注「（补充：模型常识，非文档内容）」
- mock 数据与真实数据混用时明确区分，不要把示例当制度
- 压力管理是自助放松练习，不是医疗建议；严重情绪问题建议寻求专业支持
- 题库与地图文件更新后，回答口径以最新版本为准

## 个人 All-in-One 工作台模式（给每个员工自己用，推荐优先）

> 核心视角：**不是 HR 管理后台，而是每个员工打开一个网址，就有自己的 OA + Onboarding + 破冰 + 小工具 + AI 助手**。数据落在共享 Base，但每个人看到的是「我的」。

### 个人工作台（`references/workbench/my-workbench.html`）

- **员工身份切换**：右上角选「我是谁」（张小明/李华/…），全站按「我」过滤——我的待办/审批/日程/资料、我的入职旅程进度、我的 Leader/Mentor、同部门同事
- **四大板块**：
  - 🏢 我的 OA：待办、审批、日程、我的资料（来自 HR Base 员工主档/假勤）
  - 🚀 我的 Onboarding：五站旅程进度条（破冰→工具→提问→规划→解压），说「继续」接着走
  - 💬 破冰：今日话题轮播、认识同事、团队黑话速查
  - 🧰 小工具：方块呼吸动画、BGTA 提问培训、每日一题闯关、压力管理
- **AI 天天帮我**：底部常驻对话条，关键词响应——「解压」（54321 引导）、「出题」（每日一题）、「规划」（30-60-90）、「继续」（旅程推进）、「今天干嘛」（今日安排）
- **五套风格换肤**：TikTok/Rippling/Workday/Slack/Instagram，右上角一键切换，localStorage 记忆
- **网址形态**：单文件 HTML 零依赖。交付后主动问「是否需要我帮你发布成为一个豆包工作的链接？」，同意则用「生成分享应用网站」发布成公开链接（形如 `xxx.aiforce.cloud/app/app_xxx`，每人一个链接）；也可嵌入多维表格仪表盘【内嵌网页】组件

### 与 HR Base 的分工

| 层 | 内容 | 给谁 |
|---|---|---|
| 员工主档/组织/假勤/薪酬/绩效/招聘（HR Base 11 表） | 企业数据底座 | HR 维护，员工只读「我的」视图 |
| Onboarding 五表（成长系统 Base） | 入职知识/题库/地图 | 全员共享，按人记进度 |
| my-workbench.html | 每个员工自己的 All-in-One 入口 | 一人一份 |

### 小工具市场页（marketplace.html，类 App Store）

`docs/marketplace.html`：把 chatbot 玩法中心（答题/职场测试/猜单词/互动剧情/猜拳/变形球/提神/冷知识/解压）与 onboarding 工具（旅程打卡/BGTA 提问培训/30-60-90/我的工作台/HR 工作台）整合为一个应用市场页：
- 分类：Onboarding 成长 / 互动培训 / 破冰团建 / 解压充电 / 效率协作；支持关键词搜索
- 18 个工具卡：轻量工具（呼吸 4-4-4-4 自动节拍、54321 分步着陆、答题判分、Hangman 遵守 SPIRIT 结局规范、猜拳、话题机、决策球、提神、冷知识、BGTA 生成器、旅程打卡）点开即玩（modal 内嵌）；重工具（我的工作台、HR 工作台）同目录相对链接外跳；未迁移工具显示「即将上线 · 对小笼说工具名」
- 单文件零依赖，可直接 GitHub Pages 托管

### 嵌入多维表格自定义页面（把市场页放进 Base）

Base 自定义页面（`?table=wbp...` 的页面块）添加块时支持：空白页 / 仪表盘 / 上传文件 / 飞书文档 / 飞书多维表格 / **网页**。
- **网页块（推荐）**：自定义页面 → 添加 → 网页 → 粘贴市场页公开 URL。CLI 的 `+app-block-create` 只支持 chart/text/list，**没有网页/iframe 类型，网页块只能前端手动加**（BaseApp OpenAPI 对该 Base 返回内部错误时同样走前端）。
- **公开 URL 来源**：GitHub Pages（仓库 public 后，Pages 源选分支根目录，路径形如 `https://<user>.github.io/<repo>/doubao-work/docs/marketplace.html`）；或豆包工作分享应用网站；或任意静态托管。
- **上传文件（备选）**：自定义页面 → 上传文件 → 上传 HTML（是否内嵌渲染以飞书前端实际表现为准，不渲染时退回网页块）。

## HR 全场景模式（Rippling 式 HR Base，不止 onboarding）

用户要「HR Base / 员工系统 / 假勤 / 薪酬 / 绩效 / 招聘」时，进入本模式：把多维表格 Base 升级成 HR 全场景系统，onboarding 是其中一个模块。

### 七大模块（HR Base 表组）

| 模块 | 表 | 关键字段 | Mock 条数 |
|---|---|---|---|
| 员工 | 员工主档 | 姓名/工号/部门/岗位/职级/入职日期/状态/Leader/Mentor/邮箱 | 6 |
| 组织 | 组织架构 | 团队/上级团队/负责人/人数/目标 | 6 |
| 假勤 | 假勤 | 员工/类型/开始/结束/时长/状态/审批人/事由 | 6 |
| 薪酬 | 薪酬福利 | 员工/基本工资/社保基数/餐补/交通补贴/期权/调薪日期 | 6 |
| 绩效 | 绩效 | 员工/周期/目标/自评/Leader评/评分/状态 | 5 |
| 招聘 | 招聘 | 候选人/职位/渠道/阶段/面试官/预计入职 | 6 |
| Onboarding | 见「onboarding 成长系统」五表 | 提问路径/软件/网址/日程/术语 | 59 |

### 建表动作（已实测）

1. 准备每张表的 CSV（`references/mock/11-16-*.csv`，表头即字段名）
2. `drive +import --type bitable --target-token <BASE>` 逐个 CSV 导入（**必须串行**；6 行 CSV 会被补齐到 10 条，含 4 条空记录）
3. 用 `+record-list` 定位空记录（fields 全 null），`+record-delete --yes` 清理
4. `+table-update` 把自动命名的「数据表N」改成业务表名
5. `+table-list` 回读验收：表名、记录数与字段正确

### 五风格工作台（palette 可切换）

`references/workbench/hr-workbench.html`：同一套 HR 数据，右上角一键切换五套设计语言（CSS 变量驱动，localStorage 记忆）：

- **Rippling**：浅底 + 企业蓝 #0B4DA2 卡片风
- **Workday**：浅灰 + 品牌蓝 #0077C8 + 橙 #FF8300

### 数据装载（Agent 建表 / CSV / 贴文本）

用户给数据时按这条路径走，不要只收文件就完事：

1. **上传 CSV**：读表头 → 用 `+field-list` 比对目标表字段 → 列名一致则 `drive +import --target-token` 导入；不一致或表不存在则先 `base +table-create` 建表再导入 → 清理空记录 → `+record-list` 回读验收。
2. **贴文本**：逐行解析实体（姓名/部门/岗位/日期等）→ 输出「识别到 N 行、字段 M 个」→ 问用户存进哪张表或自动匹配 → 建表/写记录 → 回读。新出现的字段口径记入「待沉淀清单」。
3. **要求「调用 agent 建表」**：明确用户意图后直接执行上述链路，不要反问「要不要我建」。

## 交互工作台（可选增强，三形态）

用户说「生成我的工作台 / 给我一个交互版」时，按需交付：

- **形态 A · 对话内交互**：直接用交互 HTML 渲染可点击模块（旅程选卡、答题判分、BGTA 评分、呼吸动画），让用户一个个选、立即获得反馈。每个交互块结尾给一个「继续对话」的落点，不把用户困在 HTML 里。
- **形态 B · 独立 HTML 工作台**：生成 `onboarding-workbench.html`（自包含、零依赖、浏览器直接打开），五站全功能 + 内置装载后的地图数据。交付为文件（用户可上传飞书云盘预览），或按下方「发布为公开链接」直接发布成豆包工作链接。
- **形态 C · Base 智能文档（onboarding Base）**：把四张地图落成多维表格数据表，题库 CSV 直接导入。已实测落地结构（5 张表，59 条 mock）：
  - `提问路径`（问题类型/示例/去哪里问/期望响应，6 条）
  - `软件清单`（优先级/类别/软件/用途/账号或安装，14 条）
  - `网址清单`（分类/名称/网址/用途/谁维护，19 条）
  - `入职日程`（天数/安排/完成标准，6 条）
  - `术语表`（术语/含义，14 条）
  - 建法：`base +base-create` 建初始表 → `+record-batch-create` 写提问路径 → 其余表用 `drive +import --type bitable --target-token <BASE>` 逐个 CSV 导入（必须串行）→ 检查空记录残留并删除 → `+table-update` 把自动命名的「数据表N」改成业务名 → `+table-list` 回读验收。
  - **HTML 嵌入 Base**：多维表格仪表盘有「内嵌网页」组件，任何可公开访问的 https URL 都可作为数据源（官方：仪表盘/应用模式中使用内嵌网页）。CLI 不支持创建该组件（dashboard 组件类型只有图表/文本/指标卡，且禁止应用模式命令），需用户在前端「仪表盘 → 添加组件 → 内嵌网页 → 填 URL」。工作台 HTML 需先托管成 URL（如豆包工作分享应用网站/静态托管）再嵌入；飞书云盘 /file/ 预览页本身不宜作嵌入源。

工作台模板与设计规范见 `references/workbench/onboarding-ui-plan.md` 和 `references/workbench/onboarding-workbench.html`（Mock 数据已内置，真实使用时替换为装载结果）。

## 发布为公开链接（可选第 4 步，所有 HTML 形态通用）

交付任何 HTML 工作台（形态 A/B、个人工作台 `my-workbench.html`、市场页 `marketplace.html`）后，**主动询问用户**：

> 是否需要我帮你发布成为一个豆包工作的链接？

用户明确同意后，用豆包工作的「**生成分享应用网站**」能力（对话里可直接说「帮我发布成链接」，或按需调用「应用生成」技能/妙搭）把 HTML 发布成公开可分享的 APP 链接，形如 `https://xxx.aiforce.cloud/app/app_xxx` 或 `https://xxx.feishuapp.cn/app/app_xxx`（绝活大会投票站就是这种形态）。交付时给出：

- **公开链接**：每人打开即用，无需安装豆包技能；适合贴在社媒、文档、Base 内嵌网页组件里
- **使用提示**：告知可嵌入多维表格仪表盘【内嵌网页】组件（任何可公开访问的 https URL 都可作为数据源）

边界与注意事项：

- **发布是公开动作**：必须等用户明确说「要」之后再发布，不要先发后问；发布前一句话说明「这会生成一个公开链接，谁拿到都能打开」
- 发布失败或用户环境不支持时，退回「交付本地 HTML 文件 + 说明如何自行托管」，不静默放弃
- 链接交付后请用户自测打开一次；需要改版时在对话里说明改哪里，发布后的链接以最新版为准
- 若用户想要的不只是静态 HTML，而是可交互/多页/带数据的应用（如投票、表单、看板），引导走「应用生成 / 妙搭」从 HTML 改造，而不是硬塞静态页
