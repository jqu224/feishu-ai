## 四、竞品 / 案例扫描（2026-09-04，提交前校准）

**飞书官方（aily / 豆包工作伙伴）**：六大主推场景——财务报销、项目管理、数据分析、HR 政策答疑、**话题群知识库答疑**（检索知识库回答 + 找不到转人工 + 写入多维表格出分析报告）、客户跟进。标杆案例 OTO 智能下单：提单 10 分钟 → 2 分钟、错误率 10% → 0%。**启示：评委心里的「好案例」= 知识库问答 + 结果沉淀到飞书文档/表格 + 可量化的前后对比数字。**我们的「知识点搜索 + 导出文档」正中这个范式，demo 必须带上量化对比。

**飞书社区 / 第三方**：WorkBuddy 教程的主推场景是「群聊讨论 → 结构化待办」「会议纪要 → 复盘文档」——对话进、文档出；n8n 零代码教程的经典卡片模式是「表单卡 → 加载中卡 → 结果卡」三段式。这些我们都有对应能力且做得更深（原地更新 + 流式）。

**GitHub**：基本都是通道/SDK 层项目（go-lark、OpenClaw、Vercel chat-sdk 适配器），**没有人做「AI 生成可交互玩法」这一层**。值得抄的细节：hermes-agent 在流式卡片底部 footer 显示「模型名 · 耗时 · token 数」，geek 感和 AI-native 感很强，成本极低。

**企业微信**：智能机器人主打知识集问答、API 接业务数据自动复盘（3 小时 → 数分钟）；敏感操作一律二次确认（Y/N）——**确认闸门是行业标准**，我们的确认卡要在 demo 里明确点出「这就是评分手册要求的人工确认」。

**抖音**：AI 分身（Coze 接入）做私信/群聊/直播答复，卖点是人格化 IP；群机器人是关键词自动回复 + 欢迎语。对我们的启示主要在传播侧（人格化称号、互动钩子），功能侧参考价值低。

**直接印证**：舜宇光学用「AI + 企业文化闯关答题」提升活动留存——答题游戏化是被企业验证过的真实场景，我们的出题/错题分析方向不是自嗨。

**扫描结论**：功能层我们领先（没人做 AI 生成可交互玩法）；差距在「叙事与证据」——量化对比数字、对标官方场景的讲解词、footer 元信息这类低成本高感知细节。

## 一、新方向：学习搭子三件套（实用绝活）

用户提出的三个功能恰好构成一条完整闭环，而且每一步都能复用现有引擎：

```
搜知识点 → 一键出题 → 群内答题 → 错题分析 → 导出飞书文档
 (search)    (AI 生成)   (quiz 引擎)  (AI 分析)    (已有导出)
```

### P0-1 知识点搜索（knowledge 意图）

- **做什么**：「帮我找一下 passenger ID 相关的知识点」→ 机器人全文检索指定资料目录（`data/kb/`，放课程笔记 / 讲义 Markdown，也可以是用户自己的文件），AI 把命中片段汇总成一张知识卡：出处文件 + 原文摘录 + AI 串讲。
- **实现要点**：新增 `src/kb.js`（启动时扫描 `data/kb/**/*.md` 建倒排索引，查询按命中度排序取 top 片段，纯本地确定性）；AI 只做「片段 → 串讲」一步；新意图 `knowledge`。
- **为什么成立**：检索是本地确定性的（不依赖 AI 不翻车），AI 只负责把搜索结果讲得更好懂——演示稳定性和实用性兼得。
- **延伸（P2）**：接飞书文档搜索 API（`suite/docs-api/search`，需 `search:docs` 权限），搜用户在飞书里的真实文档。

### P0-2 一键生成练习题（quizgen 意图）

- **做什么**：「围绕 passenger ID 出 5 道选择题」→ AI 按 `{q, options[4], answer, explain}` 出题 → **直接灌进现有答题引擎**，群里逐题作答、判分、出解析，和预制答题一模一样的体验。
- **实现要点**：新增意图 `quizgen`（输出 trivia 同构 JSON），校验后走 `buildQuestionCard` 那套状态机；加一层兜底：AI 输出不合格（答案越界/选项重复）就拒绝并提示重试。答案顺序仍走 seed 乱序，防「AI 总把答案放 A」。
- **为什么成立**：这是「AI 生成内容 × 现有交互引擎」的乘法——别家 AI 出题只能发文本，我们出完题直接能玩。

### P0-3 错题分析（review 动作）

- **做什么**：AI 出题的局结束后，结算卡多一个「生成错题分析」按钮 → 把答错的题 + 用户选项发给 AI → 生成错因分析卡（每道错题：为什么错、正确思路、同类知识点提醒），并可一键导出飞书文档。
- **实现要点**：AI 生成的题局改用 store.js 会话记录（预制局保持无状态），逐题记 `openId → 对错`；结算时汇总该玩家的错题列表 → 一次 AI 调用出分析。
- **为什么成立**：闭环的最后一环，「做完题还有人给我讲哪里弱」就是真实的学习产品。

### 三件套 vs 三个奖项

| 奖项 | 三件套的得分点 |
| --- | --- |
| 绝活之王 | 「搜 → 练 → 分析 → 导出」一条龙的完成度；检索走本地、AI 只做生成和讲解，现场怎么玩都不翻车 |
| 最佳飞书 AI Native | AI 生成的内容直接用飞书卡片交互引擎承接，错题分析一键变飞书文档——AI 在飞书里干完整件事 |
| 社媒最受欢迎 | 「我在群里@机器人出了套题，全组边摸鱼边考试」就是天然的短视频剧本；错题称号（名侦探那套）引导截图传播 |
