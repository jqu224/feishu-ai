# 组件与网址（Mock）· 去哪些网址看组件内容

> 虚构演示数据（示例科技）。真实使用时由用户自己的 onboarding 文档替换。

## 一、内部系统总入口

| 名称 | 网址 | 用途 | 谁维护 |
|---|---|---|---|
| 内网主页 | home.example.com | 所有内部系统入口、公告 | 平台团队 |
| 知识库（Wiki） | wiki.example.com | 团队文档、制度、流程 | 各团队 |
| 代码平台 | code.example.com | 代码仓库、MR/PR、CI | 研发平台团队 |
| 工单系统 | it.example.com | 账号、权限、网络、设备 | IT |

## 二、组件与设计

| 名称 | 网址 | 用途 | 适用人群 |
|---|---|---|---|
| 设计系统（Design System） | design.example.com | 色彩、字体、间距、组件规范 | 前端 + 设计 |
| UI 组件库文档 | ui.example.com/components | 前端组件 props、示例、版本 | 前端 |
| Figma 团队库 | figma.example.com | 设计稿、标注、切图 | 全员可看，设计/前端常用 |
| 图标库 | icons.example.com | 业务图标下载 | 前端 + 设计 |

## 三、文档与 API

| 名称 | 网址 | 用途 | 谁维护 |
|---|---|---|---|
| API 文档中心 | api.example.com | 后端接口定义、鉴权、限流 | 各服务 owner |
| 前端项目规范 | wiki.example.com/frontend-guide | 代码规范、提交规范 | 前端小组 |
| 后端项目规范 | wiki.example.com/backend-guide | 服务规范、发布流程 | 后端小组 |
| 数据字典 | data.example.com/dictionary | 指标口径、表结构 | 数据团队 |

## 四、平台与工具

| 名称 | 网址 | 用途 |
|---|---|---|
| 数据看板 | data.example.com/dashboards | 业务指标、报表 |
| 监控告警 | monitor.example.com | 线上服务监控、告警订阅 |
| 发布平台 | release.example.com | 服务发布、灰度、回滚 |
| 实验平台（AB） | ab.example.com | 实验配置、结果查看 |
| 日志平台 | log.example.com | 线上日志检索 |
| 财务 / 报销 | expense.example.com | 报销、审批 |
| 福利站 | benefits.example.com | 福利、制度、咨询入口 |

## 五、新人的使用顺序建议

1. 先收藏「内网主页」和「知识库」两个入口
2. 写代码前把「设计系统 + 组件库 + API 文档」加入书签
3. 上线前熟悉「发布平台 + 监控告警」的只读操作
4. 其余按任务需要再打开

> 找不到网址先在内网主页搜，搜不到走工单或问 leader。
