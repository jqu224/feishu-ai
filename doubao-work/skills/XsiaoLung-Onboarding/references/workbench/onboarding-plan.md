# Onboarding 成长系统 · 落地计划（v0.1）

> 2026-09-08 · 基于用户对项目意义的重新确认
> 一句话愿景：**新人装好一套 skill → 载入公司 onboarding 文档 → 沿旅程成长（破冰/认识/提问培训/规划/解压）→ 技能随使用自我进化。** 文档问答只是其中的「提问培训」模块，不是主角。

---

## 一、为什么是这条路

- 一次性的「文档→知识库/HTML」与评论区 70+ 作品同质，意义不大
- 真正有价值的是**可装载、可编排、可进化的 onboarding 系统**：任何公司把自己的 onboarding 文档喂进去，旅程就为它定制
- 大公司（字节跳动风格）onboarding 的刚性内容维度（用户确认）：**① 去哪里问/什么问题/该怎么问 ② 技术栈与软件安装 ③ 组件内容网址** + 支撑维度（日程/组织/术语/规划）

## 二、核心机制：Ingest → Map → Orchestrate → Evolve

```
用户 onboarding 文档（链接/粘贴/多份）
        │
  ① Ingest  抓取 → 分块 → 建索引（复用 doc-qa 五步法）
        │
  ② Map     提炼四张 onboarding 地图：①提问路径 ②技术栈与软件 ③组件与网址 ④日程与组织
        │   （输出确认，缺什么明说）
        │
  ③ Orchestrate  按旅程运行，每站一个小 APP：
        │   破冰 → 认识工具与团队(答题) → 提问培训(QA·核心) → 新人规划 → 压力管理
        │
  ④ Evolve  新 Q&A 沉淀 → 定时整理进题库/地图 → 下批新人受益（self-improve）
```

**关键设计**：Map 是灵魂。doc-qa 解决「读懂文档」，Map 解决「读懂 onboarding」——把散落内容结构化成新人真正需要问的四个维度。Mock 数据的四份文档就是四张地图的形态样例。

## 五、自我进化闭环（self-improve）

1. **沉淀**：使用中新人问的新问题、地图里没有的答案 → 记入「待沉淀清单」（对话内 + 可选 notes 文件）
2. **整理**：豆包工作「定时任务」定期触发 → 伙伴把本周新 Q&A 清洗、去重、归档进题库/地图
3. **受益**：下批新人装载同一文档时，自动获得更新后的题库与地图
4. **验证**：每次更新后跑一轮「冒烟问答」（拿 3 个高频问题验证回答口径）

不需要自建连接器：装载用内置联网，沉淀用对话记录，定期整理用定时任务，全部豆包工作原生能力。
