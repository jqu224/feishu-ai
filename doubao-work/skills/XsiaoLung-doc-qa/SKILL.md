# 小笼文档问答 · 知识库

把一个公开链接的飞书文档（或其他网页文档）变成「随时可问答的知识库」：AI 先读文档、按结构分块、建立问答索引，之后任何人提问都能得到**带出处**的回答。也可以基于文档一键出题。**全程只用一个 Skill，不需要 MCP、不需要本地服务、不需要写代码。**

## 前置条件（很重要）

- 文档必须是**公开可读**的：在飞书文档右上角「分享」→ 权限设为「互联网上获得链接的人可阅读」。未公开的链接 AI 抓不到正文，会只拿到登录页。
- 如果文档无法公开（隐私要求），用户可以把正文直接粘贴给你，同样能建知识库。
- 你需要豆包工作自带的「联网 / 网页抓取 / 浏览器」能力来打开链接——这是豆包工作的内置能力，无需额外配置。

## 五步工作流

### 第 1 步：获取文档内容

- **有公开链接**：用网页抓取能力打开链接，提取正文。优先提取：标题层级（#/##/###）、正文段落、表格、列表。去掉导航、评论区、登录弹窗等噪音。
- **只有粘贴内容**：直接用用户粘贴的正文。
- 抓取不到正文（权限不足 / 页面是纯 JS 渲染）时，如实告诉用户「链接未公开或无法抓取，请改为公开链接或直接粘贴内容」。

### 第 2 步：结构化分块

按文档的标题层级切成块，每块一个编号，格式：

```
块 1　[一级标题] 技能 / Skill 专场
块 1.1　[二级标题] 免费开源文案类 Skill 合集
块 1.2　[二级标题] 宝藏 PPT 技能
```

规则：
- 每块内容控制在 300–500 字以内，超长段落按标题或自然段再切。
- **表格要转成可读的文本清单**（如「技能名：用途，出处链接」），不要只报「有一张表」。
- 链接原样保留，回答时可作为出处引用。

### 第 3 步：建立问答索引

对每个分块提炼：
- **要点**：这一块讲了什么（2-3 句）。
- **可问问题**：这块能回答哪些典型问题（3-5 个，拟成用户会问的口语化问法）。
- **关键实体**：人名 / 技能名 / 链接 / 数字，单独列出。

输出一份「知识库索引」给用户确认，格式：

```
📇 知识库：<文档标题>（共 N 块）
- 块 1　技能 / Skill 专场 → 可问：有哪些去AI味写作技能？直播推荐了什么 PPT 技能？
- 块 2　数据分析专场 → 可问：预算评估技能在哪？数据汇总表在哪？
...
```

### 第 4 步：回答问题（核心）

用户提问后：
1. 在索引中定位最相关的块（可多个）。
2. **用原文回答**，不要用你自己记忆里的知识替换文档内容。
3. 每条回答末尾标注出处：`（出处：块 1.2「宝藏 PPT 技能」）`，有链接就附链接。
4. 文档里没有答案时，明确说「文档里没提到」，不要编造。

### 第 5 步：可选延伸

- **基于文档出题**：用户说「根据这个文档出 10 道题」→ 从各块抽取知识点出题（单选/多选/判断），每道题标注出处的块编号。
- **要点总结**：用户说「总结这份文档」→ 按块输出要点清单。
- **更新知识库**：文档更新后重新抓取一遍，替换旧索引。

## 示例话术

**建库**：「把这篇文章变成知识库：https://larkcommunity.feishu.cn/wiki/xxxxx」
→ 第 1-3 步，输出知识库索引。

**提问**：「直播里推荐了哪些 PPT 技能？」→ 第 4 步，定位「宝藏 PPT 技能」块，列全并标注出处。

**出题**：「基于这份文档出 5 道题」→ 第 5 步，从各块抽取知识点，标注出处。

**无法抓取**：「这个链接我打不开正文」→ 引导用户检查分享权限，或直接粘贴内容。

## 边界与注意事项

- 链接必须公开，否则正文抓不到——这是本技能唯一的前提，务必先确认。
- 长文档（>10000 字）分块多，回答时优先定位最相关的 1-3 块，不要全文重读。
- 表格数据别丢：报名人数、链接清单、对比表都要转成文本保留。
- 不要用文档外知识补充答案；实在需要补充时标注「（补充：来自模型常识，非文档内容）」。
- 文档含隐私内容时提醒用户：公开链接 = 所有人可见，敏感文档不要公开。
