# 入职日程与组织（Mock）· 日程、组织、术语、规划模板

> 虚构演示数据（示例科技）。真实使用时由用户自己的 onboarding 文档替换。

## 一、入职第一周日程

| 天 | 安排 | 完成标准 |
|---|---|---|
| Day 0 | 领电脑、装 P0 软件（飞书/代码平台/VPN）、账号开通、安全培训 | 能登录飞书和代码平台 |
| Day 1 | 加部门群、见 leader、了解团队目标和本周任务、读团队 wiki | 能说清团队在做什么、自己第一周做什么 |
| Day 2 | 本地起项目、跑通一次构建和测试、熟悉代码库结构 | 本地能跑起来 |
| Day 3 | 跟一个真实的 case（修 bug / 写小功能），走完提交流程 | 完成第一个 MR/PR |
| Day 4 | 参加团队周会、认识上下游关键角色 | 知道有问题找谁 |
| Day 5 | 写第一周小结（做了什么、卡在哪、下周计划）发给 leader | 收到 leader 反馈 |

## 二、组织架构（新人的上下游）

```
产品负责人 ── 需求/优先级
    │
你的团队 leader ── 目标/排期/成长
    │
你（新人）── 执行
    ├── 上游：产品（需求）、设计（视觉）、数据（口径）
    └── 下游：测试（验收）、运维/平台（上线）、客服（反馈）
```

关键角色：**leader**（目标与成长）、**mentor**（技术带教，前 3 个月）、**模块 owner**（具体模块的技术问题）、**HR 伙伴**（制度与福利）。

## 三、术语表（新人高频黑话）

| 术语 | 含义 |
|---|---|
| BGTA | 背景/目标/已尝试/请求 四段式提问模板 |
| MR / PR | Merge Request / Pull Request，代码合入请求 |
| CR | Code Review，代码评审 |
| Oncall | 值班，处理线上紧急问题 |
| 灰度 | 先小范围上线观察，再全量 |
| 回滚 | 把服务恢复到上一个稳定版本 |
| AB 测试 | 对照实验，比较不同方案效果 |
| 复盘 | 目标 vs 结果差异分析，不是追责 |
| OKR | 目标与关键结果 |
| 指标口径 | 指标的计算定义，先对齐再讨论数字 |
| 排期 | 任务的时间安排 |
| 对齐 | 达成一致的理解 |
| 冒烟 | 核心流程的快速验证 |
| 水位 | 资源/容量使用程度 |

## 四、30-60-90 天目标模板

| 阶段 | 目标 | 关键里程碑 |
|---|---|---|
| 0–30 天 · 建立基础 | 跑通环境、熟悉代码库、完成首个闭环任务 | 本地能跑、第一个 MR 合入、认识全部关键角色 |
| 31–60 天 · 端到端负责 | 独立负责一件事（从需求到上线） | 独立上线一个功能，能讲清业务价值 |
| 61–90 天 · 形成判断 | 对模块有独立判断，能提改进建议 | 主导一次小改进，产出复盘文档 |

每周五做一次 15 分钟回顾：本周做了什么 / 卡在哪 / 下周计划 / 需要 leader 或 mentor 什么支持。
